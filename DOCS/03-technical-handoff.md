# Technical handoff

For whoever productionises this. Describes what the code actually does, as of the
current build. Where this document and the product narrative disagree about intent,
this one wins — it was written from the source.

---

## 1. Stack

| Decision | Choice | Why |
|---|---|---|
| Framework | None — vanilla HTML/CSS/JS | Zero build step, instant portability, no state complex enough to warrant React |
| Styling | Hand-written CSS with custom properties | One token block drives the whole page |
| JS | ~600 lines, no libraries, one IIFE | Deliberately conservative for low-end Android in tier-2/3 markets |
| Fonts | Google Fonts (Sora, Inter, IBM Plex Mono) | The only external dependency |
| Images | Inline SVG illustrations + one JPEG | See §6 |

## 2. Repository layout

```
src/founders-desk.html   source of truth — edit this
index.html               generated by scripts/build-standalone.mjs — never edit
img/                     photographs; referenced as img/<name>.jpg from index.html
scripts/                 build + local server
DOCS/                    this folder
```

**`index.html` is generated.** Editing it directly loses your work on the next build.

### Why two HTML files

`src/founders-desk.html` targets a sandbox whose CSP blocks external images, iframes
and media. Photographs there are embedded as base64 `data:` URIs.

A self-hosted page must not do that — ~500 KB of base64 in the HTML defeats browser
caching entirely. `scripts/build-standalone.mjs` therefore:

1. wraps the source in a real `<head>`/`<body>` (the source has none — the sandbox
   supplies them),
2. rewrites `<img data-src="img/x.jpg" src="data:...">` back to `<img src="img/x.jpg">`,
3. **drops** the tag entirely where no file exists, so the deployed page issues no
   404s. The illustration fallback renders in its place.

## 3. Design tokens

Defined once in `:root`. All new work consumes these, never literals.

**The colour rule, which is load-bearing:**

- **Indigo** (`--brand`) — brand identity *and* the Build track
- **Teal** (`--sell`) — the Sell track, used only inside track-specific components
- **Amber** (`--action`) — **action, and nothing else.** Every primary CTA is amber and
  nothing that isn't a primary CTA is ever amber. There are currently 17 booking CTAs
  and 17 amber buttons; if that ratio ever diverges, something has gone wrong.

Type: `--display` (Sora) for headings, `--sans` (Inter) for body, `--mono` (IBM Plex
Mono) for eyebrows and labels.

## 4. State model

There is no state object. State lives in the DOM:

| State | Where |
|---|---|
| Programme | `#fProgramVal.value` |
| Qualifier | `#fDynVal.value` (a stable `data-value`, never display text) |
| How-it-works track | `aria-selected` on the toggle buttons |
| Quiz answers | `quizAnswers[]` in closure |
| Booking slot | `chosenDay` / `chosenTime` in closure |

**Cross-section threading:** completing the quiz, clicking a fork CTA, or following a
"better fit" crosslink all call `setFormProgram()`, which sets the hidden programme
value, swaps the visible qualifier block, **and clears any previously chosen
qualifier**. That reset is deliberate — a stale Build-stage answer must never ride
along on a Sell submission.

Nav track links deliberately do *not* set the programme. A nav click is navigation,
not a declaration of intent; it scrolls and pulse-highlights only.

## 5. Conversion architecture

Two rungs, by commitment level:

1. **Free masterclass** (`#webinar`) — two fields, name + WhatsApp. For visitors not
   ready to talk to anyone.
2. **Book a call** (`#bookModal`) — slot picker + name + phone + programme. Reachable
   from every CTA on the page.

Plus the full enquiry form (`#leadForm`) for people who prefer to write.

All three build the same payload shape and go through one `sendLead()`. They are
distinguished by an `intent` field: `webinar_register`, `book_call`, `enquiry`.

### Submission

```js
window.FD_CONFIG = { endpoint: 'https://api.example.com/leads' };
```

`FD_CONFIG` is read at startup and can be set before the script runs, or edited in
place. With `endpoint: null` (the current state) submission resolves after a simulated
delay — **no lead reaches anyone.** `forceFail: true` (or `?demofail=1`) exercises the
error and retry path without a server.

Payload:

```json
{
  "name": "string",
  "phone": "string",
  "phone_is_whatsapp": true,
  "city": "string | null",
  "program": "build | sell | unsure",
  "qualifier": "string | null",
  "notes": "string | null",
  "preferred_slot": "2026-09-07T16:00 | null",
  "consent": true,
  "intent": "enquiry | book_call | webinar_register",
  "source_path": "string",
  "utm": { "source": "", "medium": "", "campaign": "" },
  "submitted_at": "ISO-8601"
}
```

Every input carries a `name` attribute *and* is serialised explicitly in JS, so both a
native POST and a fetch work.

## 6. Images

Every person and scene is an inline SVG illustration inside a swap-slot:

```html
<span class="ph ph-48">
  <img data-src="img/mentor-rakesh.jpg" src="...">   <!-- hidden until it loads -->
  <svg role="img" aria-label="...">…</svg>            <!-- illustration fallback -->
</span>
```

`.ph img` is `display:none` until JS confirms `naturalWidth > 0`, then `.has-photo`
swaps them and the SVG gets `aria-hidden` so the photo's `alt` carries the meaning.
A missing file removes its own `<img>` — no broken-image icons, ever.

**Do not add `loading="lazy"` to these.** A `display:none` image is never "near the
viewport", so lazy loading deadlocks it: it never loads, so `.has-photo` never applies.
This was a shipped bug, since fixed.

See [04-photography.md](04-photography.md) for filenames and the consent constraints.

## 7. Accessibility

**Done:** skip link, single `h1`, semantic landmarks, `role="radiogroup"` with roving
tabindex and arrow-key support on all six option groups, `aria-describedby` on every
input, `role="alert"` on error banners and `role="status"` on success panels, focus
moved to the success panel on submit, focus trap and Escape in both modals, full
`prefers-reduced-motion` handling, 44px+ touch targets.

All measured colour pairs pass WCAG AA. If you change a token, re-measure — three
separate contrast regressions were caught this way during QA.

## 8. Browser support

Modern evergreen. Used without fallback: CSS custom properties, Grid/Flexbox, `gap`,
`grid-template-rows: 0fr→1fr` transitions (Chrome 107+/Safari 16+, degrades to an
instant open), `backdrop-filter`, `aspect-ratio`, `text-wrap: balance`,
`color-mix()`, `IntersectionObserver`.

## 9. Known limitations

1. **No backend.** `FD_CONFIG.endpoint` is `null`.
2. **WhatsApp is not wired.** Entry points route to the form. There is no Business
   number yet — do not reintroduce a placeholder `wa.me` link; an earlier version had a
   dead one and it was removed deliberately.
3. **Video ID is a placeholder** and the sandbox blocks iframes, hence the fallback
   panel. It plays inline on normal hosting.
4. **Proof is illustrative.** Stories, mentors and the message thread are placeholders,
   labelled as such in three places.
5. **Programme structure is proposed** — cadence, phases and deliverables were never
   confirmed by the business.
6. **"One working day" is an operational promise** appearing in seven places with no
   staffing behind it.
7. **No rate limiting.** A honeypot is in place; the rest needs the backend.
